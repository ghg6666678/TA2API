# 稳定性与运行机制

> 本文只描述**当前代码实际具备**的机制，以及仍然真实存在的边界。
>
> 原 `docs/` 里那套「五层上下文控制」（长对话存档、体积折叠、流空闲看门狗、自动续接、
> 熔断、内核池）属于历史设计稿，**代码未实现，且已判定不需要投入**：那些问题的实测
> 前提是「内核把一次回复攒成整块快照下发」，`d0b78f4` 改为消费 `message.part.delta`
> 逐字增量之后，长上下文与中途静默都不再复现。相关记录保留在 [GAPS.md](GAPS.md)。

## 一、内核看门狗（进程级）

`TA_WATCHDOG_MS`（默认 `15000`）周期性检查内核进程是否还活着：

- **判据**：`proc.exitCode !== null || proc.signalCode != null`。
  必须同时看 `signalCode`——进程被信号杀死（`SIGKILL` / OOM killer）时，Node 只设
  `signalCode`，`exitCode` 会保持 `null`。早期版本只看 `exitCode`，在 Linux 容器里
  表现为「容器 Up、所有请求毫秒级 `502 fetch failed`，而看门狗永远不触发」。
- **动作**：重启内核并刷新 `/healthz` 里的内核端口，后续请求自动走新实例。
- **实测**：Windows `taskkill` 后约 28 秒恢复；Linux 容器 `kill -9` 后约 11 秒恢复。

## 二、先起后换（按客户端类型 + 提示词指纹）

内核按「客户端类型 + 系统提示词 sha」决定是否需要切换。切换严格按「先起新的、
就绪后再关旧的」执行，中途失败不会留下空窗；切换动作经串行链排队，避免并发请求
互相杀掉对方正在预热的内核。

代价：跨协议交替调用会触发换核（chat → responses → messages 各一次），每次 1–2 秒，
并清空挂起的工具会话。以同类客户端为主时基本感觉不到。

## 三、会话映射与 TTL

按 `user` 字段或「首条用户消息」指纹复用内核会话，TTL 6 小时。
三协议会话按 `chat:` / `codex:` / `anthropic:` 前缀隔离，互不串台。

> 模型名不参与指纹——这点很重要：若参与，同一段对话换个别名就会新建会话、历史断掉。

## 四、流式输出

内核有两条路上报内容，网关都消费：

| 事件 | 含义 | 处理 |
|---|---|---|
| `message.part.delta` | 真正的**增量**文本（逐字） | 直接转发；正文与思维链按 `partID` 分流 |
| `message.part.updated` | **累积全文快照** | 与已发长度比对，只补差集（防丢帧、不重复） |

两路同时在跑时，快照看到长度已到位就跳过，因此不会重复；`delta` 偶发丢帧时，
下一次快照会把缺口补齐。代理对每个 delta 直接 `res.write`，不做任何攒批或定时平滑。

> 历史结论已作废：早期只消费快照时，上游网关会把一次回复按「思考段 / 正文段」整块刷出，
> 表现为「蹦几句 → 卡一会 → 再蹦几句」。改为消费 `delta` 后，这个现象不再出现，
> 原先据此设计的流空闲看门狗也不再需要。

## 五、仍然存在的边界

以下都是**当前真实存在**、但日常几乎碰不到的限制：

| 场景 | 表现 | 说明 |
|---|---|---|
| 上游真的断流 | 连接挂着不返回 | 没有流空闲超时，只能等或客户端自己放弃；逐字增量后极少见 |
| 多客户端并发 | 单内核串行排队 | 没有内核池；同类客户端共享一个内核，轮次之间排队 |
| 跨协议交替调用 | 换核 1–2 秒 | `chat` / `codex` / `anthropic` 交替会触发；同时挂起的工具会话会被清空 |
| 超长对话 | 历史整体发给内核 | 交给内核自身的 compaction 处理；长会话实测正常，不再有「必卡 240 秒」 |

## 排障速查

| 现象 | 看哪里 | 处置 |
|---|---|---|
| 所有请求毫秒级 `502 fetch failed` | 进程/容器是否 Up；内核是否还活着 | 内核死了但代理没察觉 → 确认 `TA_WATCHDOG_MS` 没被设成 `0`，且代码含 `signalCode` 判据 |
| 请求长时间不返回 | 内核日志最后一行的时间戳 | 上游确实断流；没有流空闲超时，客户端重试即可 |
| `401 {"code":"need_login"}` | 管理台「登录态」面板 | token 缺失：在 TeleAgent 桌面版登录一次，再重启反代 |
| token 到期前后请求 401 | 管理台「登录态」 | 在桌面版重新登录一次即可，反代 60 秒内自动跟随 |
| `400 unknown model` | 客户端模型配置 | 只接受 `chat-pro` / `chat-flagship` / `chat-flash`，见 README 模型表 |
