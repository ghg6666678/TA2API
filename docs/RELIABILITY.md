# 稳定性与运行机制

> 本文只描述**当前代码实际具备**的机制。曾经设计但尚未实现的那套上下文控制
> （流空闲看门狗、自动续接、长对话存档与检索、熔断、内核池）见 [GAPS.md](GAPS.md)。

## 一、内核看门狗（进程级）

`TA_WATCHDOG_MS`（默认 `15000`）周期性检查内核进程是否还活着：

- **判据**：`proc.exitCode !== null || proc.signalCode != null`。
  必须同时看 `signalCode`——进程被信号杀死（`SIGKILL` / OOM killer）时，Node 只设
  `signalCode`，`exitCode` 会保持 `null`。早期版本只看 `exitCode`，在 Linux 容器里
  表现为「容器 Up、所有请求毫秒级 `502 fetch failed`，而看门狗永远不触发」。
- **动作**：重启内核并刷新 `/healthz` 里的内核端口，后续请求自动走新实例。
- **实测**：Windows `taskkill` 后约 28 秒恢复；Linux 容器 `kill -9` 后约 11 秒恢复。

## 二、先起后换（按客户端类型 + 提示词指纹）

内核按「客户端类型 + 系统提示词 sha」决定是否需要切换。切换严格按「先起新的、
就绪后再关旧的」执行，中途失败不会留下空窗；切换动作经串行链排队，避免并发请求
互相杀掉对方正在预热的内核。

代价：跨协议交替调用会触发换核（chat → responses → messages 各一次），每次 1–2 秒，
并清空挂起的工具会话。以同类客户端为主时基本感觉不到。

## 三、会话映射与 TTL

按 `user` 字段或「首条用户消息」指纹复用内核会话，TTL 6 小时。
三协议会话按 `chat:` / `codex:` / `anthropic:` 前缀隔离，互不串台。

> 模型名不参与指纹——这点很重要：若参与，同一段对话换个别名就会新建会话、历史断掉。

## 四、已知的稳定性边界

以下都**没有实现**，遇到时需要客户端重试或人工干预：

| 场景 | 当前表现 | 缺什么 |
|---|---|---|
| 上游长时间静默 | 代理不超时、不报错，连接挂着 | 流空闲看门狗 |
| 静默后上游断开 | 客户端收到错误，需手动重试 | 自动续接 |
| 超长对话（数万字符以上） | 整体发给内核，`chat-pro` 可能长时间无响应 | 体积折叠 / 历史存档 |
| 单条超大工具结果 | 原样发送 | 工具结果截断 |
| 同一会话反复失败 | 每次都重试一次 | 熔断 |
| 多客户端并发 | 单内核排队服务 | 内核池 |

这六项的设计思路、阈值与实测数据保留在 [GAPS.md](GAPS.md) 的稳定性章节。

## "输出一顿一顿"是上游网关行为

逐 chunk 计时实测（小 prompt 即复现，代理逐 delta `res.write`、无任何攒批）：

| 场景 | 思维链到达 | 正文到达 | 最长静默 |
|---|---|---|---|
| 41 字符 prompt · chat-pro | 1,111 字 = **2 个 chunk** | 489 字 = **2 个 chunk** | 11.0 秒 |
| 41 字符 prompt · chat-flash | 546 字 = **2 个 chunk** | 520 字 = **2 个 chunk** | 10.3 秒 |
| 35k 会话重放 · chat-pro | 66,500 字 = **2 个 chunk** | 964 字 = **2 个 chunk** | **163.9 秒** |

首 token（如 `"Let"`）总能在 1–3 秒单独到达 → 代理与内核都不缓冲；
静默期是**网关在上游整段缓冲**，按"阶段"（思考段 / 正文段）结束才整块刷出。
思考型模型的长回答会交替经历多个阶段，于是表现为"蹦几句话 → 卡一会 → 再蹦几句"。

代理无法也没有必要"平滑"它——数据没到就写不出来，人为拆成定时小包只会增加延迟。
代理本身对每个 delta 都直接 `res.write`，不做攒批；也因此当前**没有**流空闲超时机制，
遇到长时间静默只能等，或由客户端自己放弃。

## 排障速查

| 现象 | 看哪里 | 处置 |
|---|---|---|
| 所有请求毫秒级 `502 fetch failed` | 进程/容器是否 Up；内核是否还活着 | 内核死了但代理没察觉 → 确认 `TA_WATCHDOG_MS` 没被设成 `0`，且代码含 `signalCode` 判据 |
| 请求挂住不返回 | 内核日志最后一行的时间戳 | 上游静默；当前没有流空闲超时，只能客户端重试 |
| `401 {"code":"need_login"}` | 管理台「登录态」面板 | token 缺失或已清空，用「用 Cookie 登录」恢复 |
| 手动续期报 `40115` | 管理台横幅 | 容器内属常态（服务端只认官方客户端），token 仍可用至到期，届时重新导入凭据 |
| 输出整块蹦出 | — | 上游网关行为，见上文，无需处理 |
| `400 unknown model` | 客户端模型配置 | 只接受 `chat-pro` / `chat-flagship` / `chat-flash`，见 README 模型表 |
