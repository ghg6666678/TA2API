三、内核二进制 ELF 鉴定（关键结论）
-----------------------------------
用 Python 直接读 ELF Program Header：
  x64:   class=2 (ELF64) machine=0x3e (x86-64)  PT_INTERP=None  PT_DYNAMIC=False
  arm64: class=2 (ELF64) machine=0xb7 (aarch64) PT_INTERP=None  PT_DYNAMIC=False
结论：两个架构的内核均为完全静态链接，不依赖 glibc/GTK/X11。
      → 可用 distroless/scratch 类最小镜像，无需在容器内装桌面库。
      → 这也是"官方 Linux 二进制移植到 Docker"能成立的根本原因。

sha256（本工作区实测）：
  super-agent-code-linux-x64.tar.gz      38d0faee9c471f403511c4a6e0c46dcce950da544bb530986f7282815c4c3a9d
  super-agent-code-linux-arm64.tar.gz    5bfa6ff4b060e5ae6cb633bb59b8a39a8d71458611d556327a79f00d7b287938
  解包后 TeleAgent(x64)                  26f1008b4066c45a1eb5f193261d5aa78f1b4a5dab3c7040d924ec66c4c11b40
  解包后 TeleAgent(arm64)                fd3a5f979305645d5b4ec847762276a5407ad055f735e89a1ae5bdd09aafaffc

重要（避免误用 hashes）：deb 内 runtimes.version.json 写的是
  superAgentCodeHash = 26f1008b... = 解包后 x64 内核二进制的 sha256
  superagentChecksum = 38d0faee... = x64 tar.gz 的 sha256
即版本文件里的两个 hash 一个是"包"一个是"二进制"，名字相近但含义不同。

五、TA2API v0.3.3 中与部署相关的现状（源码核对）
-----------------------------------------------
lib/paths.mjs:
  KERNEL_BINARY = ~/.local/share/TeleAgent/runtimes/super-agent-code/bin/TeleAgent
                  （Linux 上文件名不带 .exe，正好匹配 deb 解包产物）
  DEVICE_DATA_ROOT = ~/.local/share/TeleAgent
  resolveOwner() 读 current-owner.json；tokenFile 指向 users/<owner>/app-auth/token.json
lib/kernel.mjs startKernel():
  spawn(KERNEL_BINARY, [], {cwd, env, stdio:[inFd,outFd,errFd]}) —— 无命令行参数
  配置通过 stdin：4 字节大端长度 + JSON（含 SERVER_PORT、SUPER_AGENT_AUTH_STATE 等）
  origin = http://127.0.0.1:<随机或指定端口>
  SUPER_AGENT_APP_DATA_DIR / CONFIG_DIR 指向 DEVICE_* 根
lib/auth.mjs:
  dpapiMasterKey() 调用 powershell.exe + System.Security.ProtectedData 解 DPAPI 主密钥
  decryptV10() 用该密钥做 AES-256-GCM 解 token.json 里的 encryptedToken
  → Linux 无 DPAPI，这是 v0.3.3 直接上 Linux 的硬障碍
lib/shim.mjs:
  createShim 形参 host='127.0.0.1'；server.listen(port, host)
  server.mjs 调 createShim 时未传 host → 实际固定 127.0.0.1
  → 容器端口映射访问不到；需最小补丁把 host 提到 env（见部署指南）
server.mjs 现有 env（全清单）：
  TA_ADMIN_TOKEN, TA_ALLOW_KERNEL_TOOLS, TA_API_KEY, TA_BUILTIN_PROMPT,
  TA_DEBUG_DIR, TA_DEFAULT_MODEL, TA_FALLBACK_PROMPT, TA_GATEWAY_KEY,
  TA_KEYS_FILE, TA_OPEN_ADMIN, TA_PORT, TA_TIMING, TA_UPSTREAM_BASE_URL
  不存在：TA_ADMIN_ALLOW_REMOTE / TA_CRYPT_KEY / TA_REQUIRE_AUTH / TA_RENEW_*

七、局域网访问限制的真实性
--------------------------
用户判断"原项目似乎不支持局域网访问"属实，且有两层：
  1) shim 固定绑 127.0.0.1（server.mjs 未传 host，shim.mjs 默认回环）
  2) 内核 origin 也固定 127.0.0.1（kernel.mjs）
但这是"代理层/内核层"的绑定，与官方 CLI 无关；在容器里给 shim 加 host=0.0.0.0
即可通过 docker -p 暴露。docs/ADMIN.md 里的 TA_ADMIN_ALLOW_REMOTE 是未来设计，
当前不可用。
